# Avito Antiscam Simulator

Симулятор-тренажер для пользователей, предназначенный для обучения выявлению мошенников и предотвращению фишинговых схем. В процессе работы пользователь проходит через типовые сценарии обмана (покупка электроники, продажа товаров, аренда недвижимости), по результатам которых формируется оценка уровня бдительности.

## Инструкция по локальному запуску

Проект контейнеризован. Для локального развертывания требуются Docker и Docker Compose.

1. Клонирование репозитория:
   ```bash
   git clone https://github.com/Chaice1/Avito-Antiscam-Simulator.git
   cd Avito-Antiscam-Simulator
   ```

2. Запуск сервисов:
   ```bash
   docker-compose up -d --build
   ```
   База данных и кэш инициализируются автоматически при первом запуске (таблицы создаются через `schema.sql`).

3. Локальные адреса после успешного запуска:
   - API (Бэкенд): `http://localhost:8080`
   - База данных (PostgreSQL): `localhost:5432`
   - Клиентская часть (React): `http://localhost:5173` (nginx в Docker Compose; при запуске через `npm run dev` тот же порт)

## Перечень используемых технологий

**Backend:**
- Язык: Go (Golang) 1.22+
- База данных: PostgreSQL 15 (хранение данных пользователей и истории прохождений)
- Кэширование: Redis 7 (управление состоянием активных сессий)
- Маршрутизация: Стандартный `net/http` ServeMux
- Драйвер БД: `pgx/v5`

**Frontend:**
- Фреймворк: React + TypeScript
- Сборщик: Vite
- Стилизация: Ant Design + inline-стили

**Инфраструктура:**
- Docker, Docker Compose
- Railway / Render (Deployment)

## Особенности реализации

1. Графовая архитектура диалогов: Сценарии реализованы в виде направленных графов в формате JSON. Приложение динамически обходит узлы графа в зависимости от ответов пользователя.
2. Stateful-сессии в Redis: Каждое прохождение игры создает уникальную сессию с TTL 15 минут в Redis, что обеспечивает быстрый доступ к текущему состоянию диалога без нагрузки на реляционную БД.
3. Безопасность: Использование драйвера pgx напрямую, без ORM, для предотвращения SQL-инъекций и оптимизации запросов.
4. Масштабируемость: Бэкенд и фронтенд разделены на независимые сервисы.
5. Контейнеризация фронтенда: Фронтенд собирается в мультистейджинге Docker (Node.js → сборка, nginx → раздача статики), nginx проксирует запросы `/api/` на сервис `backend`.

## Распределение ответственности в команде

- **Никита**: Разработка модуля `user` (`backend/internal/user`).
  - Проектирование схемы базы данных PostgreSQL.
  - Реализация функционала регистрации пользователей и сохранения статистики прохождений.
  - Настройка Docker, Docker Compose, деплой на сервера (Railway/Render) и маршрутизация DNS.
  
- **Кирилл**: Разработка модуля `simulator` (`backend/internal/simulator`).
  - Проектирование и реализация алгоритма обхода графов диалогов.
  - Настройка и интеграция Redis для управления состоянием текущей сессии.
  - Реализация бизнес-логики сценариев и подсчета итоговых баллов.

- **Андрей**: Разработка клиентской части (`frontend`).
  - Реализация интерфейса симулятора диалогов, страницы выбора сценариев, прогресса и результатов.
  - Интеграция фронтенда с API бэкенда и мок-режим при недоступности сервера.
  - Реализация 15-минутного таймера прохождения и деталей попыток.
  - Контейнеризация фронтенда: Dockerfile, nginx-конфигурация, подключение в Docker Compose.
